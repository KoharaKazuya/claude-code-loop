## 判断内容

`.agent/<種別>/<ID>.md` を `.agent/archive/<種別>/<ID>.md` へ移動する際、移動先に同名ファイルが
既に存在する場合は移動せずにスキップし、`RotateResult.conflicts` として報告する。
`runRotate` は衝突 1 件につき警告ログを 1 行出す。衝突が解消されるまで片付けのたびに同じ警告が出る。

## 理由

- ファイル名 = ID は他ファイルからの参照キー(タスクの `dependencies`、判断の `tasks` / `review`、
  本文中の ID 参照)である。書庫側・移動側のどちらをリネームしても、これらの参照が指す先が
  失われる。参照の張り替えは機械的に完遂できない(本文の自由記述にも ID が現れる)。
- スキップは可逆で、両方の記録がそのまま残る。人間が内容を見比べて手で解決できる。
- 警告が毎回出ることが「人間が気づける」の担保になる。1 回だけの通知だと見落とされる。

## 検討した代替案

- **末尾に `-2` を付けて退避**: ID 採番規約(`disambiguateId`)と同じ形なので一見自然だが、
  上記のとおり既存ファイルからの参照を壊す。新規採番時の衝突回避と、既に参照されている記録の
  移動とでは前提が違う。
- **内容が同一なら黙って捨てる**: 判定コストの割に効果が薄く、「同一に見えて実は違う」ときに
  記録を失う。単純さを優先して採らなかった。

## 影響範囲

- 衝突したタスク・Review はアクティブ側に残り続ける(completed / closed のまま)。一覧を読む
  セッションのコンテキストがその分だけ増えるが、衝突は人間の手作業由来の稀なケースであり許容する。
- 衝突した判断は `decisions/index.md` の行が `[x]` のまま残る。行を消すと実体ファイルが残っている
  ため次回リコンサイルで未チェックとして復活し、人間が付けたチェックが失われる。
