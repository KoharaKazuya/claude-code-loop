## 判断

`ccloop run` の想定される使い方は「起動したターミナルをそのまま開いておく」ことである。
バックグラウンドジョブとして裏で動かすことは推奨しない。

停止の導線は現状(起動した画面で Ctrl+C)のまま増やさない。ループのプロセス番号を状態として
記録し `ccloop status` に表示する案は**採用しない**。

## 理由

人間の回答による(`HR-20260830-0429-topic-run-stop-handle`)。
「このままで。ドキュメントに『裏で動かす』というバックグラウンドジョブの推奨みたいな記述が
あれば修正して。ccloop run を起動したターミナルを起動しっぱなしにする使い方を想定している」。

「止めたいときは信号を送る。ファイルを置いて止めるような仕組みは持たない」という既存の方針
(`README.md`)も維持される。

## 影響範囲

- `lib/help.ts` と文書にある「裏で動かすとよい」と読める記述は改める
  (`T-20260830-0621-background-run-wording`)。
- 今後の探索セッションは、停止の導線を増やす提案(プロセス番号の記録・表示、停止用の
  サブコマンド、停止ファイル)を**再提案しないこと**。
- `run` が常駐プロセスであるという事実の説明は必要なので残す。変えるのは推奨の部分だけである。
