## 判断

タスクの `dependencies` に、現役の `.agent/tasks/` にも `.agent/archive/tasks/` にも存在しない
ID が書かれている場合、スケジューリング上は従来どおり「充足」として扱い、タスクを実行する。
検出結果は `ccloop status` の「要対応」と `ccloop list` の deps 行(淡色にしない)で人間に見せる。

## 理由

- 存在しない依存を「未達」にすると、そのタスクは人間がファイルを直すまで永久に実行されない。
  人間が status を見ていない間、ループが静かに空回りする方向へ倒れる。
- 一方、実行してしまっても失われるのは「順序の指定」だけで、成果物は残り、やり直しも効く。
  可逆性はこちらが高い。
- 打ち間違いは人間しか直せない。ループを止めるより、止めずに気づかせるほうが噛み合う。

## 検討した代替案

- 存在しない依存を未達にして実行を止める: 上記のとおり、静かに止まるリスクが大きいため採らない。
- 依存を自動で削る / 自動補正する: 人間の意図(どのタスクを待たせたかったか)を推測することになり、
  黙って書き換えるぶん現状より悪い。

## 影響範囲

`depSatisfied` と `planTaskSelection` の挙動は変えていない。追加したのは検出用の純粋関数
`findMissingDependencies` と、`ccloop status` / `ccloop list` の表示のみ。
「archive にある完了済みタスクへの依存は充足のまま」はテストで固定した。
