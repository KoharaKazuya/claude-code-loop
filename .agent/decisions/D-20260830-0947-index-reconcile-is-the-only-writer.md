## 判断内容

`.agent/decisions/index.md` に未掲載の決定を載せる責任を、`lib/rotate.ts` の
`rotateDecisions()`(ローテーションのリコンサイル)だけに持たせる。セッションに手で追記させる
手順は `lib/prompt/PROMPT.md` から外し、「追記はしない」と明記した。新しい仕組みは作っていない。

## 理由

調査の結果、当初の仮説(「手順書が index.md への追記を求めていないから載らない」)は誤りだった。
実際には両方あった。

- `lib/prompt/PROMPT.md` は「決定ファイルを作成したら index.md に 1 行追記する」を作成者の義務として
  求めていた。
- `lib/rotate.ts` のリコンサイルは、実体ファイルにあって index.md に無い ID を未チェック行として
  ID 降順の正しい位置へ機械的に追加する。この実装が正しく動くことは、実データ(`.agent/decisions/`
  のコピー)に対して `rotate()` を実行し、未掲載 6 件が期待どおりの位置・要約で追加されることを
  確認して裏を取った。

未掲載が実際に発生していた原因は仕組みの欠落ではなく、**稼働中の ccloop が公開版 0.4.1 の
インストール済みビルド(`/usr/local/share/ccloop/lib/`)で、そこにはリコンサイルも index.md の
概念自体も無い**ためである(そのビルドの decisions ローテーションは「新しい 10 件を残して残りを
アーカイブ」という件数基準で、index.md を読まない)。この乖離は `ccloop status` の
「インストール済みと乖離」警告が既に伝えている。

仕組みが二重にある状態で、片方(セッションの手作業)は忘れが起こりうるうえ、index.md の同一領域を
並走セッションが触る唯一の原因でもある。機械側だけで完全に賄えるので、手作業の側を落とした。

## 検討した代替案

- **手順書の義務を残したまま強調する**: 忘れの再発をセッションの注意力で防ぐことになり、タスクの
  完了条件(注意力に頼らない)を満たさない。採らない。
- **`ccloop status` に「未掲載の決定」を表示する**: status は既に `.agent/decisions/` の実体ファイルを
  数えて「未承認の決定」を出しており、index.md の掲載状況に依存しない。掲載漏れを別枠で出しても
  同じ情報の二重表示にしかならない。採らない。
- **`.agent/` の自動コミット時に未掲載分を追記する**: リコンサイルと同じ処理を別の契機に足すだけで、
  書き込み経路が増えて衝突の機会も増える。採らない。

## 影響範囲

- `lib/prompt/PROMPT.md`: 決定記録の節から手動追記の義務を削除。
- `docs/architecture.md`: index.md の 3-way マージの説明が「セッションが追記するため衝突する」という
  実態と違う前提に立っていたので、リコンサイルが書き手であること・3-way マージは手編集への
  安全網であることに直した。
- `lib/rotate.test.ts`: 既存 index.md への追記(未チェック行が ID 降順の正しい位置に入る)の
  リグレッションテストを追加。
- `.agent/decisions/index.md`: リポジトリ側のソースでリコンサイルした結果に更新。未掲載 6 件を追加し、
  実体が archive へ移った 17 行を削除した(削除分は `.agent/archive/decisions/` に全件あることを確認済み)。

なお公開版 0.4.1 が動いている間は、決定が件数基準で(人間のチェックと無関係に)アーカイブされる。
次のリリースでこの挙動は無くなる。過去にそうしてアーカイブされた決定は
`.agent/archive/decisions/` に残っており、内容は失われていない。
