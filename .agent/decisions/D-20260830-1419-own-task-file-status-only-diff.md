## 判断内容

衝突解消セッションが自分の担当タスクファイルを更新するとき、main 側の内容を丸ごと採用し、
`status` の 1 行だけを書き換える。`note` は main 側(ccloop が書いた「マージ衝突が続くため
ready に戻す(N/5)」)のまま残す。

## 理由

`note` はマージ基点に存在せず、main 側と自分の側が同じ位置へ別々の 1 行を挿入する形になるため、
両方が書き換えると次のマージで必ず衝突する。衝突すると 1 セッション分の時間が丸ごと解消作業に
消える。一方 `status` は main 側が基点から変えていないので、自分の側だけが変えれば自動マージが
通る。`conflictRetries` と `## 試行履歴` は main 側と同一内容をそのまま持つことで衝突しない。

完了したタスクは次のローテーションでアーカイブへ移るため、`note` の文面が古いことによる実害は
`ccloop status` 上の短時間の表示だけであり、マージ 1 回分のコストより小さい。完了内容の説明は
コミットメッセージに残す。

## 検討した代替案

- `note` も完了内容へ書き換える: 表示は正確になるが次のマージが確実に衝突する。採らない。
- `git merge-tree` で衝突有無を事前確認する: `Bash(git merge*)` が deny に含まれるため実行できない
  (`T-20260830-1407-narrow-readonly-git-deny-patterns` が扱う制約そのもの)。

## 影響範囲

衝突解消セッション全般。`lib/prompt/PROMPT.md` の該当箇所は「自分が変えたい frontmatter
(status / note)だけを上書きする」と書いており、`note` の書き換えを許している。本判断はその
範囲内でさらに絞る運用であり、ルール変更は伴わない。
