## 確認事項

一言でいうと: **「実行中のタスクの記録ファイルには触るな」というルールを、お願いベースから
仕組みで止める形に変えてよいか。**

### なぜ聞いているか

改善のネタごとに確認を取る運用にしている。これは内部の安全策を足す話だが、
実現の仕方によっては「触れないファイルがある」という制約が利用者にも見える形になるため、
リリースノートに 1 行載る粒度に当たると判断した。

### いまどうなっているか

ccloop は複数のセッションを同時に走らせる。あるタスクを実行中のセッションと、
全体を見渡す探索セッションが同時に動くことがある。このとき探索セッションが
実行中タスクの記録ファイルを書き換えると、両者の変更がぶつかる。

これを防いでいるのは**指示文だけ**である。探索セッションに渡すプロンプトへ
「実行中のタスクの一覧」を載せ、「これらは編集しないこと」と書いている。
コード側にそれを強制する仕組みは無く、書き込もうとしても止まらない。

### 何が困るか

指示に従わなかった場合に何が起きるかは、編集した場所による。

- 同じ行を両方が書き換えた場合は、統合の仕組みが「衝突」として止めるので気づける。
- **別々の行を書き換えた場合は、両方の変更が静かに混ざる。** 片方が「まだ作業中」と書き、
  もう片方が「完了」と書いた記録が、そのまま 1 つのファイルに同居しうる。

実際にこの取り違えが起きた記録はまだ無い。あくまで「守られる保証が無い」という話である。

### やるとしたら何をするか

実行中のタスクの記録ファイルへの書き込みを、仕組みとして拒否する(書き込もうとした時点で
止める)。または、書き込まれたことを後から検出して知らせる。

### 気にしている点(ここが確認したい理由)

止める仕組みを足すと、正当な理由で書き換えたい場面(例: 明らかに壊れた記録を直したい)まで
止めてしまう。守りを固くするほど融通が利かなくなる、という設計上の綱引きがあり、
どちらを取るかは好みの問題に近い。

### やらない選択もある

実害が出た記録はまだ無く、同じ行なら統合の仕組みが止めてくれる。指示文で足りている、
という判断もありうる。

## 暫定判断

回答があるまでこのトピックのタスクは作らない。他の作業は止めずに進める。
