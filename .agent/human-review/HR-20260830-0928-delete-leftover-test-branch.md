## 確認事項

一言でいうと、**中身が空っぽのゴミブランチが 1 本残っているので消してほしい**という依頼です。

いま、テストを走らせるとこのリポジトリ本体にブランチが作られてしまう不具合を直しています。
その過程で、過去にテストが作ったと思われるブランチが本体に残っているのを見つけました。

当初 5 本(`T-001` / `agent/T-001` / `agent/T-002` / `agent/T-003` / `agent/T-999`)ありましたが、
このセッションの調査中に `agent/` 付きの 4 本は消えていました(ccloop 自身の孤児ブランチ回収が
片付けたと思われます)。**残っているのは `T-001` の 1 本だけ**です。

削除して問題ないことは確認済みです。根拠は次のとおりです。

- `T-001` の先端は `a9f32aa`(「Merge branch 'agent/T-20260830-0558-explore-session-spawn-uncaught'」)で、
  これは**過去の main そのもの**です。
- `git log main..T-001` の結果が空でした。つまり **`T-001` にしかないコミットは 1 つもありません**。
  このブランチを消しても、失われる作業は何もありません。単に「過去の main を指す付箋」が消えるだけです。

ブランチの削除はセッションの権限外なので、人間の手で実行をお願いします。

```
git branch -D T-001
```

(念のため、実行前に `git log --oneline main..T-001` が空であることを確認していただければ確実です。
空でなければ実行せず、その旨をこのファイルに書いてください。)

## 暫定判断

削除は人間が行うものとして、セッション側は削除せずに残しています。
残っていても実害は出ていません(対応するタスクファイルが無いため、ccloop の孤児ブランチ回収は
このブランチを本物の作業成果とは扱わず、警告に落とすだけです)。ただしテストの残骸と本物の作業
ブランチが同じ場所に同居している状態は紛らわしいため、片付けたいと考えています。

再発防止側の対応(テストが本体にブランチを作れないようにする、作ったら自動で検出して
テストを失敗させる)は、このセッションで実装済みです。
