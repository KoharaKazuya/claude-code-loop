## 確認事項

一言でいうと: **バックグラウンドで動かしたループを、安全に止められるようにしてよいか。**

### なぜ聞いているか

改善のネタごとに確認を取る運用にしている。これは使い方(止め方)が変わる話で、
リリースノートに 1 行載る粒度に当たる。

### いまどうなっているか

説明書に書かれている停止方法は「ループを起動した画面で Ctrl+C」だけである
(`README.md:64-78`)。一方でツール自身は「ループは裏で動かすことを推奨」と案内している
(`lib/help.ts:34-35`)。

裏で動かすと Ctrl+C を送る画面が無い。ループがどのプロセスとして動いているかはどこにも
記録・表示されていないため、止めたい人は自力でプロセスを探して停止信号を送るしかない。

なお実装は Ctrl+C 以外の停止信号でも同じように「区切りのよいところまで進めてから止まる」
挙動になっている(`lib/supervisor.ts:3211-3212`)が、これは説明書のどこにも書かれていない。

### 何が困るか

- 止めたいのに止め方が分からない。手探りで別のプロセスを巻き込んで止めてしまう危険がある。
- 乱暴に落とすと、作業途中のセッションの成果が中途半端な形で残る。

### やるとしたら何をするか

1. ループの居場所(プロセス番号)を状態として記録し、`ccloop status` に「動いています(止めるにはこう)」
   の形で表示する。
2. 説明書に「Ctrl+C 以外の停止信号でも同じように安全に止まる」ことを明記する。

### 気にしている点(ここが確認したい理由)

いまの設計は「止めたいときは信号を送る。ファイルを置いて止めるような仕組みは持たない」と
意図的に決めている(`README.md:76-78`)。今回の案はその方針は変えず「止め先を見えるようにする」
だけだが、停止の導線を増やす話ではあるので、方針の持ち主に一度確認したい。

### やらない選択もある

ループを画面の中で動かして使う限り Ctrl+C で足りる。裏で動かすのは主にエージェント向けの
使い方なので、人間向けの導線としては不要という判断もありうる。

## 暫定判断

回答があるまでこのトピックのタスクは作らない。他の作業は止めずに進める。

## 回答してほしいこと

**ループの居場所を `ccloop status` に表示し、停止方法を説明書に補う対応を進めてよいか。
不要ならそう答えてほしい。**

## 回答

このままで。ドキュメントに「裏で動かす」というバックグラウンドジョブの推奨みたいな記述があれば修正して。ccloop run を起動したターミナルを起動しっぱなしにする使い方を想定している。
