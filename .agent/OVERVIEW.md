# OVERVIEW(GOAL に対する現在地)

GOAL の「現在の目標」1 つ目(decisions アーカイブの人間承認化、`ccloop status` への未承認決定の
表示)は完了済み。2 つ目の「人間の確認・介入の導線を磨く」も、足りない機能を作る段階は概ね
抜けている。いま残っているのは次の 3 種類である。

## 1. 導線が手元に届いていない(最大の綻び。回答を得て着手可能になった)

`ccloop` の実体はインストール先のコピーであり、リポジトリの `lib/` を直しても入れ替えるまで
人間の手元の挙動は変わらない。入れ替え手順は README にも docs にも書かれていない。公開版 0.4.1 から
未公開の変更が積み上がっている。他の作業がいくら進んでも手元に届かないため、残る綻びの中では
最も重い。ready の中でこの系統を最優先(p2)に置いている。

- 入れ替え手順: `T-20260830-0342-local-ccloop-update-docs`。回答は「1」= **文書化のみ**で、
  入れ替え用サブコマンドは作らない。
- 変更履歴: 回答は「作る」。`CHANGELOG.md` の新規作成と過去分の遡及まとめ
  (`T-20260830-0341-changelog-initial`)、以後の更新運用のルール化
  (`T-20260830-0341-changelog-update-rule`)に分割済み。

## 2. 検証の信頼性

- GOAL の制約「deny リストと PROMPT.md の絶対ルールを常に一致させる」の検証テストは追加済み。
- テストの無かった hook 3 件へのテスト追加も完了。
- 残る空白は **セッション終了時の後始末(マージ結果 × 実行結果 × マージ中断の十数分岐)の配線**
  (`T-20260830-0318-finish-task-session-wiring-tests`)。壊れると main やコミット済みの成果を
  失いうる箇所で、検証の空白としては現状で最大。個々の純粋関数は切り出されテスト済みで、
  未検証なのはそれらを組み合わせる配線である。

## 3. 実装と仕様の細かな食い違い(残り)

- `.agent` の自動コミットをスキップする際、自分が加えたステージを戻さない
  (`T-20260830-0318-commit-agent-dir-unstage-on-skip`)。「人間の並行作業を保護する」という
  設計意図と逆の結果になっている。
- `ccloop add` のオプション入力に検証が無い(`T-20260830-0337-add-option-input-validation`)。
  特に `--deps "T-a, T-b"` のように空白を挟むと存在しない ID が登録され、依存関係が
  何のエラーも出さずに無効化される。
- 自動マージが `.agent/decisions/index.md` だけを機械的に解決した場合も、ログには
  「タスクファイルはブランチ側を採用」と出る(`T-20260830-0337-merge-mechanical-resolution-log`)。
  コミットメッセージ側は正しく、食い違うのはログ表示だけ。
- worktree 側の git 操作中断の検出範囲が本体側より狭い
  (`T-20260830-0318-worktree-git-operation-detection`)。影響は限定的。
- 探索セッションの瞬時クラッシュが系統故障検知の対象外になっている件は、意図的な設計か
  見落としか断定できていない(`T-20260830-0337-explore-session-crash-detection`。まず意図の
  確定が目的)。
