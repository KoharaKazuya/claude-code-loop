# OVERVIEW(GOAL に対する現在地)

GOAL の「現在の目標」1 つ目(decisions アーカイブの人間承認化、`ccloop status` への未承認決定の
表示)は完了済み。2 つ目の「人間の確認・介入の導線を磨く」も、機能面では
`lib/prompt/PROMPT.md` の仕様と実装の間に食い違いがほぼ無いところまで来ている
(Human Review の Stage 1/2/3、decisions の承認とローテーション、タスク frontmatter の各フィールド、
`## 試行履歴` への機械追記、権限拒否の記録と status への要約表示を、今回の探索で 1 件ずつ
突き合わせて確認した)。

つまり「作るべき機能が足りない」段階は概ね抜けている。いま残っているのは次の 3 種類である。

## 1. 導線が手元に届いていない(最大の綻び)

`ccloop` の実体はインストール先のコピーであり、リポジトリの `lib/` を直しても入れ替えるまで
人間の手元の挙動は変わらない。現に、未承認の決定の表示も、乖離を知らせる警告そのものも、
リポジトリ側では動いているが手元の `ccloop status` には出ない。入れ替え手順は README にも
docs にも書かれていない。公開版 0.4.1 から未公開の変更が 27 コミット分たまっている。
→ `HR-20260830-0303-topic-local-ccloop-update`(要回答)

## 2. 検証の信頼性

- 自己ホスト環境で親セッションの `CLAUDE_AGENT_*` が子プロセスへ漏れ、`stop-check` のテストが
  そこでだけ失敗する(`T-20260830-0254-test-env-isolation-session-vars`、対応中)。
- GOAL の制約「deny リストと PROMPT.md の絶対ルールを常に一致させる」に検証手段が無い。
  現時点の内容は一致しているが、片方だけ更新されても誰も気づけない
  (`T-20260830-0259-deny-list-prompt-consistency-test`)。
- テストの無い hook が 3 つ残っている(`T-20260830-0254-hook-scripts-regression-tests`)。

## 3. 仕様書と実装の表記不一致

`lib/prompt/PROMPT.md` が機械追記の見出しを「ccloop 記録」と引用しているが、実装が書くのは
「Supervisor 記録」。全セッションが読む仕様書の記述が実物と違う
(`T-20260830-0259-attempt-record-label-mismatch`)。
