## 確認トピックの在庫(枠が空き次第そのまま HR にすればよい)

調査済みで根拠も揃っているが、確認枠が満杯のためまだ人間に投げていないもの。
どちらも「壊れている」のではなく仕様の選択なので、修理として勝手に進めないこと。

1. **記録が増え続けると状況表示が重くなる件**。実行のたびに追記される記録
   (`metrics.jsonl` / `permission-denials.jsonl`)と、片付け済みのタスク置き場
   (`.agent/archive/tasks/`)を、`ccloop status` と `ccloop watch` が毎回**全件**読んで
   集計している(`lib/supervisor.ts` の `loadMetrics` / `loadPermissionDenials` /
   `loadArchivedTasks`)。`watch` は既定 1 秒間隔なので、長く使うほどじわじわ遅くなる。
   無制限運用はコード内のコメントで明示された当初の選択であり、覆すなら確認が要る。
2. **複数のリポジトリで同時にループを回すと、利用上限の待機が共有されない件**。
   待機の状態はリポジトリごとの状態ディレクトリに保存されるが、実際の利用上限は
   アカウント単位で課される。そのため片方が待機に入っても、もう片方は上限中のまま
   セッションを起動し続ける。共有する仕組みを入れるかどうかは設計上の選択。
