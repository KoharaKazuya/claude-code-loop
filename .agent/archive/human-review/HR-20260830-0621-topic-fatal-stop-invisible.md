## 確認事項

一言でいうと: **ループが致命的な理由で自分から止まったとき、その事実を `ccloop status` で
後から分かるようにしてよいか。**

### なぜ聞いているか

改善のネタごとに確認を取る運用にしている。これは `ccloop status` の表示内容が変わる話で、
リリースノートに 1 行載る粒度に当たる。

### いまどうなっているか

リポジトリ本体が git 操作の途中で固まり、自己修復も失敗すると、`ccloop run` は
「人間の git 操作が進行中、または巻き戻し不能。対処後に再起動すること」とログして
自分からループを止める(`lib/supervisor.ts:3419-3429`)。

ところがこの文言は画面に表示されるだけで、どこにも保存されない。しかも終了時の後始末
(`lib/supervisor.ts:3646-3659`)が「ループが動いていた」という記録そのものを消してしまう。

そのため後から `ccloop status` を見ても、一度も起動していない場合と全く同じ
「ループ本体: 動いていません (ccloop run が起動していません)」としか出ない
(`lib/liveness.ts:292-299`)。「要対応」の一覧にも、本体が異常停止したことを示す項目は無い。

### 何が困るか

止まった理由は画面を閉じた瞬間に失われる。裏で動かしている場合、翌朝 `ccloop status` を
見ても「起動していない」以上のことが分からず、異常に気づけない。

### やるとしたら何をするか

致命的な理由で自分から止まったことを状態として保存し、`ccloop status` で
「異常停止しました(理由)」のように分かるようにする。「要対応」の一覧にも本体の異常を足す。

### 気にしている点(ここが確認したい理由)

直す方向自体に議論の余地は薄い。ただし、今の「起動していません」という文言とどう区別して
見せるか、「要対応」に何をどう足すかは表示の設計判断であり、確認したい。

### やらない選択もある

固まるのは稀な状況で、そのときは画面に文言が出ているのだから、その場で読めば十分という
考え方もある。
