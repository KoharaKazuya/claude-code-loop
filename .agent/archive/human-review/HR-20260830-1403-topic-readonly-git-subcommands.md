## 確認事項

一言でいうと、**エージェントに「見るだけ」の git コマンドまで禁止してしまっている箇所があるので、
そこだけ緩めてよいか**の確認です。

### なぜ確認するか(この確認の趣旨)

開発を 4 段階に分け、段階の区切りであなたに感想・中断・方針変更の機会を作る運用にしています。
いまは最終段階(思いつく改善すべて)で、この段階では改善案を 1 件ずつお伺いを立ててから着手します。
今回はその 1 件です。**この確認が止めているのはこの案のタスク化だけ**で、他の作業は止まりません。

### いま何をしているところか

自律セッションには「やってはいけない操作」の一覧があり、事故防止のため
ブランチの切り替え・マージ・作業場所の作成などを機械的に禁止しています。この一覧は
「`git マージ` で始まるコマンドは全部だめ」のような前方一致で書かれています。

その結果、**名前がたまたま同じ書き出しになるだけの「見るだけのコマンド」まで巻き添えで禁止**
されていることが分かりました。具体的には次の 3 つです。

- 枝分かれした地点を調べるコマンド(`git merge-base`)— マージはせず、共通の祖先を表示するだけ
- どんな衝突が起きるか事前に試算するコマンド(`git merge-tree`)— 何も変更しない
- 作業場所の一覧を表示するコマンド(`git worktree list`)— 作らない・消さない
- 退避した変更の一覧を表示するコマンド(`git stash list`)— 出し入れはしない

実害も出ています。前回の探索セッションは、作業場所まわりの調査で
「一覧を見ることすらできないので実機で確かめられず、コードを読んで推測するしかなかった」と
記録を残していました。しかも ccloop 自身のプログラムは、まさにこの一覧表示コマンドと
枝分かれ地点を調べるコマンドを内部で使っています(`lib/worktree.ts` と `lib/supervisor.ts`)。
つまり **その部分の不具合を調べるセッションが、自分の手では同じ状況を再現できない**状態です。

### 提案する変更

禁止の書き方を「`git マージ` で始まるもの全部」から「`git マージ` そのもの(と引数付き)」に狭め、
上に挙げた見るだけの 4 コマンドを通します。**実際に変更を加えるコマンド(マージの実行、作業場所の
作成・削除、退避の出し入れ)はこれまでどおり禁止のまま**です。禁止一覧とセッション向けの説明文の
食い違いは自動テストで検出される仕組みがあるので、両方そろえて直します。

### 判断材料(緩めることの裏側)

- 良い点: 衝突・作業場所まわりの調査が実機でできるようになり、推測で書かれた修正が減ります。
  この領域は過去に何度も事故(衝突で成果が取り残される)が起きている場所です。
- 気になる点: 「禁止一覧を狭める」変更そのものです。狭めた結果、意図せず変更を伴うコマンドが
  通るようになっては本末転倒なので、そこは実装時にテストで固めます。
- なお、セッションが自分の判断で禁止を緩めることは規則で禁じています。だからこそ**この変更は
  あなたの同意が必要**で、勝手に進めません。
