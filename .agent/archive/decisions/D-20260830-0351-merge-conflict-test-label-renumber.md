## 判断内容

`lib/supervisor.test.ts` の `describe("recoverStartupIn")` で、main と
`agent/T-20260830-0318-finish-task-session-wiring-tests` が独立に新規テストを追加し、
どちらも先頭ラベルを `K:` にしたため追加同士の衝突になった。

両方のテストを残し、main 側の `K:` / `L:` をラベルそのままで先に置き、ブランチ側の
wedged テストを `M:` へ改番した。両側の `it()` 本文は変更していない。

## 理由

内容の対立ではなくラベル空間の衝突であり、どちらのテストも独立した分岐を検証している。
片方を捨てるとカバレッジが減る。「迷う箇所は main 側を優先する」の趣旨は既に main に
入った成果を壊さないことなので、main 側のラベルを固定し後発を改番するのが最小の変更になる。

## 検討した代替案

- ブランチ側を捨てて main 側だけ残す: wedged 分岐(`merge --abort` 自体の失敗)の検証が
  失われる。このタスクの完了条件そのものなので却下。
- ラベル(`K:` 等)を全廃して説明文だけにする: 衝突の再発は防げるが、このファイルの
  既存テスト A〜J すべての改名を伴い、衝突解消セッションの範囲を超える。

## 影響範囲

`lib/supervisor.test.ts` のテスト名のみ。実装コードへの影響はない。
同じ describe ブロックへ今後テストを足す場合は `N:` から続ける。
