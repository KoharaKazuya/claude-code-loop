## 判断内容

`ccloop status` の「インストール済みの ccloop がこのリポジトリの lib/ と一致していない」警告は、
このリポジトリで開発している間ほぼ常に点灯する。これを異常とみなさず、常時点灯のまま運用する。

## 理由

`docs/architecture.md`「このリポジトリ自身も公開 feature 経由で ccloop を使う理由」のとおり、
インストール済みコピーとリポジトリ `lib/` の乖離は**意図的な設計**である(自己改変で実行中の
ツールが壊れないようにするため)。したがって乖離そのものは異常ではない。

一方で人間側には「`ccloop status` の出力が、いま書いたコードではなく固定バージョンの挙動である」
ことが見えていなかった。実装・マージ済みの機能が status に出ず「壊れている」と誤解される事故が
実際に起きた(未承認決定 7 件が表示されなかった件)。警告はこの誤解を防ぐための常設の但し書きで
あり、消すべき異常の通知ではない。文言も「要対応」ではなく事実の提示に留めてある。

## 検討した代替案

- 乖離の程度(バージョン差)で出し分ける: インストール済み側にリポジトリのバージョン情報が無く、
  比較できるのはソースのハッシュのみなので実装できない。
- `ccloop run` 中のみ表示する: 人間が status を見るのは run の外が多く、目的を果たさない。

## 影響範囲

`collectStatusData()` / `formatStatus()`。誤警告の防止は判定側で担保している(自己ホストと
判定できない、またはソースから直接起動している場合は警告しない)。将来この警告を
「消すべきバグ」として扱わないこと。
