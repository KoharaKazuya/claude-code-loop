## 判断内容

`classifyTaskSessionResult` の判定順を レートリミット → 衝突未解消(mergeStuck)→ 時間切れ →
それ以外 に確定した。

## 理由

同一の失敗種別問題を別々に直した 2 つのブランチが衝突したため、両者を 1 つの順序に統合した。

- レートリミットが最優先: 失敗として数えない(retries を消費しない)うえ待機時刻の設定が必要で、
  他の種別で先に拾うと同じ状況を繰り返す。
- 衝突未解消は時間切れより先: 次の試行に渡す申し送りが「衝突を解消せよ」でなければならず、
  「タスクを分割せよ」では的外れになる。時間切れであった事実は reason の末尾に併記する。

## 捨てた変更

このブランチのテスト「レートリミット + 時間切れは timeout になる(従来の優先順を維持する)」を
削除し、rate-limited を期待する形に書き換えた。このテストが固定していた「従来の優先順」は
main 側が不具合として修正済みであり、前提が失効していたため main 側を優先した。
検証を弱める変更ではない(同じ入力に対する期待値を、修正後の正しい挙動に更新したもの)。
3 種同時成立(レートリミット + 衝突未解消 + 時間切れ)のテストを新たに追加した。

## 影響範囲

`lib/supervisor.ts` の結果分類のみ。`nextFastCrashStreak` は目的が異なるため
時間切れを先に見る従来のままでよい(その旨は関数の doc コメントに記載済み)。
