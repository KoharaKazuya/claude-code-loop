## 判断

生存記録(`runner.json`)に `/proc/<pid>/stat` の starttime を**生の文字列トークンのまま**
`procStartToken` として保存し、`ccloop status` 側で現在の同 PID のトークンと照合する。
食い違えば「別プロセスが同じ PID を使っている」とみなし `stopped` にする。

## 理由

D-20260830-0425(心拍設計)では「PID の存在確認 + 心拍の鮮度」で実用上足りると判断し、
`/proc` の参照は Linux 依存が増えるとして却下していた。この判断はレビューで覆った。
2 つの保護は独立していない。`ccloop run` が `process.exit(130)` などで `finally` を経ずに
死ぬと心拍は新しいまま残るため、鮮度チェックは何も守らない。その猶予内に無関係な別プロセスが
同じ PID を取ると「動いています」と誤表示される。心拍が最も新しい瞬間ほど誤判定しやすい。
これはこの機能で最も避けたい誤りなので塞ぐ価値がある。

## 検討した代替案

- **starttime を epoch 時刻に換算して `startedAt` と突き合わせる**: HZ(clock tick)と boot 時刻の
  取得が必要で、HZ を 100 と決め打つと環境次第で大きくずれ、生きているのに「動いていません」と
  出る側の誤りを招く。生トークンの同値比較なら同一 boot 内で一意に定まり、換算が要らない。
- **`ps -o lstart=` で照合**: `ccloop watch` は既定 1 秒間隔で status を呼ぶため、毎回プロセスを
  起動するのは割に合わない。`/proc` の読み取りは安い。

## 影響範囲

Linux 以外やトークンが取れない環境では照合をスキップし、従来どおりの判定に落ちる。
トークンを持たない古い記録も同様。取れないことを理由に判定を厳しくはしない(後方互換のため)。
すなわちこの変更は誤検出を増やさず、誤った「動いています」だけを減らす。
