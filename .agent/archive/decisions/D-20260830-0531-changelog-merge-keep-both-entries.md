## 判断内容

`CHANGELOG.md` の「## 未リリース > ### 修正」節末尾で起きたマージ衝突を、両側の項目を
**どちらも残す**形で解消した(main 側の「探索セッションの時間切れ表示」を先、ブランチ側の
「片付けの衝突時に上書きしない」を後)。

## 理由

衝突の実体は「同じ箇所への独立した追記」であり、どちらかを捨てる理由が無い。変更履歴は
利用者向けのリリースノートなので、両方の修正が公開版に含まれる以上、両方載るのが正しい。

「解消に迷う箇所は main 側を優先する」という共通ルールは、同じ対象を互いに書き換えた場合の
指針である。今回は排他的な書き換えではなく追記同士なので、片方を捨てる形では適用しない。
順序は main 側を先に置き、ブランチ側の追記を後ろに足す形にした。

## 検討した代替案

- main 側だけを残す: ブランチ側の修正が変更履歴から漏れ、リリース時に利用者へ伝わらない
- ブランチ側だけを残す: 同上(main 側の修正が漏れる)

## 影響範囲

`CHANGELOG.md` のみ。コードの挙動には影響しない。

## 付随して行ったこと

タスクファイル `T-20260830-0509-archive-move-overwrites-existing.md` は、ブランチ側と main 側
(ccloop が失敗記録として `retries: 1` と `## 試行履歴` を追記していた)で内容が分かれていた。
main 側を土台に採用し、`status` と `note` だけを完了状態へ更新した。ccloop が機械的に付けた
記録を捨てないためであり、次回のマージで同じ箇所が再衝突するのを避けるためでもある。
