## 目的

全セッションが読む仕様書(`lib/prompt/PROMPT.md`)が、実装と食い違う文字列を引用している。
仕様書に書かれたとおりに grep しても該当箇所が見つからないため、後続セッションが
自分の読み方を疑って余計な調査に入る。小さいが、仕様書の信頼性に直接響く。

### 1. 試行履歴の機械追記ラベル(本題)

- `lib/prompt/PROMPT.md:297,299` は、ccloop が機械的に追記するエントリの見出しを
  「ccloop 記録」と説明・引用している(`### 未コミット差分(<時刻>, ccloop 記録)` など)。
- 実装が実際に書き出す文字列は「Supervisor 記録」である
  (`lib/supervisor.ts:1381` `appendAttemptRecord`、`lib/supervisor.ts:1425`
  `appendUncommittedDiffRecord`)。テストもこの実装文字列をアサートしている
  (`lib/supervisor.test.ts:701,712,3051`)。
- この文字列は書き出し専用であり、`lib/` 内に読み戻す(パースする)処理は無いことを確認済み。
  したがって実装側の文字列を変更しても解析ロジックは壊れない。

**揃える方向は実装側を「ccloop 記録」に変えることを推奨する。** 理由は、この文字列が
タスクファイルに残って人間とセッションの両方に読まれる表示文字列であり、`Supervisor` は
内部クラス名で外向きの語彙ではないため。ただし最終判断は実装時に行い、逆方向(PROMPT.md を
実装に合わせる)を選ぶ場合はその理由を `.agent/decisions/` に残すこと。

実装側を変える場合、既存のタスクファイルに残っている「Supervisor 記録」の行はそのまま
放置してよい(過去の記録であり、書き換える必要はない)。

### 2. 存在しないテストファイルへの言及(ついで)

- `lib/help.ts:8` のコメントが「cli.test.ts / help.test.ts から参照される」と書いているが、
  `help.test.ts` は存在しない。実態に合わせてコメントを直す。

## 完了条件

- 上記 2 件の食い違いが解消されている。
- 1 について実装側を変更した場合、対応するテストのアサーションも更新されている
  (テストを削除・弱体化させないこと)。
- `npm run typecheck` / `npm run lint` / `npm run test` が通る。
