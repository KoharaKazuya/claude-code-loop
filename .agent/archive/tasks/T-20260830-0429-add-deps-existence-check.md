## 目的

`ccloop add --deps` に存在しないタスク ID を渡しても `add` は成功し、依存が黙って
無効化されるのを防ぐ。

## 現状

`parseDeps`(`lib/supervisor.ts:3590` 付近)はカンマ区切りの文字列を trim・分割するだけで、
実在するタスク ID かどうかを見ていない。呼び出しは `cmdAdd`(同 3617 行付近)の 1 箇所。

存在しない ID を書いたタスクは、依存が満たされないまま永久に選ばれない。人間が
`ccloop list` を開いて `(missing)` 表示に気づくまで分からない(`lib/supervisor.ts:3687` 付近)。
`add` した本人には成功メッセージしか出ない。

## 完了条件

- `ccloop add --deps` の各 ID を実在するタスクと突き合わせ、存在しないものがあれば
  エラー終了する(どの ID が見つからなかったかをメッセージに出す)。
- 突き合わせ先には `.agent/archive/tasks/` の完了済みタスクも含める。完了済みタスクへの
  依存を書けなくなると、既存の使い方を壊すため。
- 回帰テストを追加する(存在する ID は通る / 存在しない ID は落ちる / 完了済み ID は通る)。
- `npm run` 経由の test / typecheck / lint が通る。
- 利用者から見た挙動が変わるので `CHANGELOG.md` の「## 未リリース」節に 1 行足す。

## 補足

`ccloop list` 側の `(missing)` 表示は残す。`add` を経由せず人間が直接タスクファイルを
書く経路があるため、表示による検出は引き続き必要である。
