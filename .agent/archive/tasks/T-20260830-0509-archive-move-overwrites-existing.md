所属フェーズ: 4(思いつく改善すべて)。記録を失う不具合の修理なので人間の確認は取らない。

## 症状

`moveToArchive`(`lib/rotate.ts:49-58`)は `.agent/<種別>/<ID>.md` を
`.agent/archive/<種別>/<ID>.md` へ `fs.renameSync` で移動するが、移動先に同名ファイルが既に
あるかを確認していない。POSIX の `rename` は移動先を黙って上書きするため、書庫側の記録が
無警告で失われる。

## 起こりうる経路

CLI 経由の新規作成は `disambiguateId`(`lib/ids.ts`)が `.agent/archive/` も含めて ID 衝突を
避けるため、この経路では起きない。実際に踏むのは人間・エージェントが `.agent/tasks/*.md` を
手で作成・複製・復元する運用(このリポジトリが前提としている運用)である。旧形式 ID の再利用や、
書庫から現役の置き場へ戻したファイルを再度片付けたときに衝突しうる。

## やること

移動先に同名ファイルが存在する場合に上書きしない。衝突時の扱い(スキップして警告 / 別名を付けて
退避 のどちらか)は実装セッションが決めてよいが、**記録を失わないこと**と**人間が気づけること**を
満たすこと。選んだ理由は `.agent/decisions/` に短く残す。

## 完了条件

- 移動先に同名ファイルがある状態で片付けを走らせても、既存の記録が失われないことをテストで確認する
- 衝突が起きたことが実行ログから分かる
- `npm run` 経由の typecheck / lint / test がすべて通る
