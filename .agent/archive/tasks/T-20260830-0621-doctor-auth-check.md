## 背景

`ccloop doctor` は Claude Code が呼び出せるかどうかしか見ていない(`lib/doctor.ts:152` 付近)。
この確認は**ログインしていなくても成功する**(実機確認済み)。そのため未ログイン・認証切れの
環境でも doctor は全項目 ✓ を返し、その後ループを回すとタスクが片っ端から失敗する。
失敗はやり直し回数を消費するので、気づいたときには複数のタスクが `failed` になっている。

## やること

1. ログイン状態を確認する手段を調べる。**確認方法そのものの挙動が未調査**なので、まず
   `claude` CLI で副作用なく短時間に判定できる方法があるかを実機で確かめること。
   見つからない、または判定が不安定なら、無理に実装せず 3. の代替に切り替えてよい。
2. doctor に検査項目を 1 つ足す。doctor は「副作用が無く、すぐ終わる診断だけを行う」方針で
   作られている(`lib/doctor.ts:8-10`)ので、その方針に収まる形にすること。
   **誤警告を出すくらいなら見ないほうがまし**という前提を守る。特に、環境変数の API キーだけで
   動かしている使い方を「未ログイン」と誤判定しないこと。判定に自信が持てない場合は
   ✗(失敗)ではなく注意喚起にとどめる、といった倒し方も検討してよい。
3. 1. で確実な判定方法が無いと分かった場合の代替: タスクが認証まわりで失敗したときの
   メッセージを分かりやすくする(「ログインしていない可能性がある」と示す)。この場合は
   doctor には手を入れず、判断の理由を `.agent/decisions/` に記録すること。
4. テストを足す。実際の認証状態に依存しない形で(判定関数に結果を注入できる構造にするなど)。
5. `docs/` の doctor の検査項目一覧と `lib/help.ts` の記述に食い違いが出ないよう合わせる。
6. 利用者から見た挙動が変わるので `CHANGELOG.md` の「## 未リリース」に 1 行足す。

## 完了条件

未ログイン環境で `ccloop doctor` が問題を示すこと(または 3. の代替が入っていること)。
誤警告が出ないことを、少なくとも API キー利用の想定について検討した上で結論を残すこと。
機械的検証が通ること。
