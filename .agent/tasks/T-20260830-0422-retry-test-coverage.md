## 経緯

`ccloop retry`(実装コミット `ac489d0`)のレビューで、実装は APPROVE だが 3 つの分岐が
テストで担保されていないと指摘された。実装側の不具合は見つかっていないので、追加するのは
テストだけでよい。

## やること

`lib/cli.test.ts` の `ccloop retry(子プロセスで検証)` describe に、既存テストの書式・命名に
合わせて次を追加する。実装コードは変更しない。

- **失敗理由の 20 行切り詰め**: `## 試行履歴` に 25 行以上ある `### 試行 1` エントリを持つ failed
  タスクで retry を実行し、stdout が 20 行に切り詰められ「(以下略)」を含むこと。あわせて
  20 行以内なら「(以下略)」が出ないことも確認し、境界を押さえる。
- **archive にしか無いタスクの案内**: `.agent/archive/tasks/<id>.md` にのみ存在する ID を指定
  したとき exit 1 で、stderr が `.agent/archive/tasks/` への退避を伝えていること。
- **「もしかして:」の出力書式**: 似た ID のタスクを `.agent/tasks/` に置いた状態で存在しない ID を
  指定し、stderr に「もしかして:」とインデント付きの候補 ID 行が含まれること。インデント漏れ等の
  書式崩れを検出できる形にすること。

## 完了条件

- 上記 3 分岐のテストがあり、`npm run typecheck` / `npm run lint` / `npm test` が通る。
- テストを緩めて通すことはしない。実装側の不具合が見つかった場合は実装を直す。
