## 症状

セッションが失敗すると実行ログにはセッション ID と stderr の末尾 200 文字(`stderrTail`)だけが
出る。それ以上を追うには Claude Code の記録(transcript)を見る必要があり、コード中のコメントも
そう案内している。

- `lib/supervisor.ts:481`「claude-code-log(README 参照)でセッション ID から確認できる。」
- `lib/supervisor.ts:1868`「claude-code-log(README 参照)で確認する。」

しかし `README.md` にも `docs/` にも該当の説明が無い(grep で確認済み)。README を ccloop 前提に
全面改訂したコミット `9fbd9ad` で当該節が消え、以後復元されていない。

削除された当時の記述は次の内容だった(Git 履歴より)。

> セッションが失敗した際は、Supervisor が出力するセッション ID を使い、claude-code-log で
> セッションログを確認できる。タスクセッションは worktree(`<repo>-worktrees/<タスクID>`)で動くため、
> ログは `~/.claude/projects/` 配下のそれに対応するプロジェクトディレクトリに記録される

## やること

「セッションが失敗したときにログをどう追うか」を説明書へ戻す。ただし当時の文面をそのまま
復元するのではなく、**現在の実装で正しいこと**を確認してから書くこと。

- セッション ID がどこに出るか(実行ログ・`ccloop status` のどちらに出るか実装で確認する)
- 記録がどのディレクトリに置かれるか(タスクセッションは worktree で動くためパスが本体と異なる)
- 参照手段として `claude-code-log` を今も案内してよいか(存在しない道具を指し続けるくらいなら、
  記録ファイルの場所を示すだけでもよい)

書き先は README か `docs/` のいずれか適切な方。docs/ の運用ルール(`.claude/CLAUDE.md`)に従い、
過去の経緯は書かず現在の事実だけを書く。コード側のコメントが指す先(「README 参照」)と実際の
書き先が食い違わないよう、必要ならコメントの文言も直す。

## 完了条件

- 失敗したセッションのログにたどり着く手順が説明書に書かれている
- 書かれた手順が現在の実装と一致することを確認した(推測で書かない。確認できなかった点は
  書かずに落とす)
- `lib/supervisor.ts` のコメントが指す先が実在する
- `npm run` 経由の typecheck / lint / test がすべて通る
- 説明書の記述改善のみなので `CHANGELOG.md` には載せない
