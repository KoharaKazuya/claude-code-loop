所属フェーズ: 4(思いつく改善すべて)。人間の同意は
`HR-20260830-0621-topic-status-grows-slow` で取得済み。ただし回答で
**「とくに archive されたものは優先度は低い」**と明示されているため、他の作業をすべて
押しのけてまで着手しない。

## 何が起きているか

`ccloop status` / `ccloop watch` は、片付けて `.agent/archive/tasks/` へ移した完了済みタスクを
毎回全件読んで進捗の集計に使っている(`lib/supervisor.ts` の `loadArchivedTasks`)。
タスクは 1 件 1 ファイルなので、使い込むほどファイル数に比例して読み込みが増える。

## やること

1. 全件読まずに進捗の数を出せるようにする。案は複数ありうる(件数だけを別に持つ、
   frontmatter だけを読む、読む件数に上限を設ける等)。どれを選ぶかは実装時に判断し、
   理由を `.agent/decisions/` に記録する。
2. **進捗バーの完了数・総数が変わってしまわないこと**を優先する。ここは「直近ぶん」に
   置き換わると意味を失う数字なので、読む量を減らしても総数は正しく出せる方法を選ぶ。
   どうしても正確さを落とすしかないなら、その旨を `.agent/human-review/` に REVIEW として上げる。
3. 大量の書庫タスクがある状態で進捗が正しく出ることを確かめるテストを足す。

## 完了条件

書庫のタスクが増えても `ccloop status` / `ccloop watch` の読み込み量が抑えられ、
進捗の数字はこれまでと変わらないこと。機械的検証が通ること。
