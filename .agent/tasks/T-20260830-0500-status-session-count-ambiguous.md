## 目的

`ccloop status` の「稼働状態」ブロックで、**同じ「セッション数」というラベルが 5 行以内に 2 回出て、
異なる値を示している**。実測(2026-08-30T05:00Z 時点)の出力:

```
-- 稼働状態 --
セッション数: 45 / 最終探索: 2026-08-30T04:58:40.546Z
直近セッション: cost=$5.5390 / turns=8
累計: cost=$145.8231 / セッション数=44
```

読んだ人はどちらが正しいのか判断できず、どちらかが壊れていると受け取る。実際にはどちらも正しく、
数えているものが違う。

## 現状の実装

- `lib/supervisor.ts:4886` — `state.sessionCount`。これまでに**起動した**セッションの総数で、
  今まさに動いているセッションも含む。
- `lib/supervisor.ts:4911` — `metrics.length`。`metrics.jsonl` に**計測行が書かれた**セッション数で、
  終了したものだけが対象。累計 cost はこの母数に対する合計である。

差分は「起動済みだがまだ終わっていない(=計測行が無い)セッション」の数。上の例では探索セッション
自身が走っている分の 1 件。`metrics.jsonl` はローテーションしない無制限運用(`lib/supervisor.ts:2027`
のコメント)なので、過去分が削られて減ることは無い。

## 完了条件

- 2 つの値が何を数えているのかがラベルから区別できる。特に累計 cost の母数がその行の件数である
  ことが読み取れる(cost はサブエージェントを含む合計である点は既存の実装コメント参照)。
- 同じ値を 2 か所で出すのが冗長なら、片方を落とす形で解決してもよい。どちらを残すかは実装者の
  判断でよいが、稼働状態の行から「最終探索」の情報は落とさないこと。
- 表示のテスト(`lib/supervisor.status.test.ts`)に、2 つの件数が区別できることを確かめる検査を足す。
- `npm run typecheck` / `npm run lint` / `npm test` が通る。
- `CHANGELOG.md` の「## 未リリース」に利用者向けの 1 行を追加する。

## 補足

表示文言だけの変更であり、`state.json` や `metrics.jsonl` の形式・集計ロジックは変えなくてよい。
`--json` 出力(`collectStatusData`)のキーは利用者が参照している可能性があるため変えないこと。
