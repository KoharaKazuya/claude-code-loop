所属フェーズ: 4(思いつく改善すべて)。既にある挙動が説明されていないという欠落の修理であり、
人間の確認は不要(挙動そのものは変えない)。

## 背景

`ccloop run` は、実行可能なタスクが無く、探索セッションを起こす条件も満たさず、スヌーズ中の
タスクも無いとき、待ち続けるのではなく**ループそのものを終了する**(`lib/scheduler.ts` の
`planLoopStep` が `{type: "stop", cause: "idle-exit"}` を返し、`lib/supervisor.ts` の `mainLoop` が
break してプロセスが終わる)。再開は人間が `ccloop run` を打ち直す必要がある。

この挙動は README にも `docs/` にも書かれていない(`README.md:161` に `idlePollMs` の説明が
あるだけ)。利用者から見ると「放置していたらいつの間にかループが終わっていた」という状況になり、
異常終了と区別できない。実行ログには案内が出るが、ログを見ていなければ気づけない。

## やること

README(停止について書いてある節が適切)に、次の 3 点が読み取れる短い説明を足す。
`docs/architecture.md` にスケジューラの判断を説明している箇所があれば、そちらに書くほうが
適切かを判断して決める(両方に重複して書かない)。

- やることが尽きるとループは自動的に終了する(異常ではなく設計どおり)
- 終了しない条件(スヌーズ中のタスクがある、探索を起こす条件を満たす)
- 再開の方法(`ccloop run` を打ち直す)

docs/ 運用ルールに従い、量を増やしすぎないこと(数行で足りる)。コードから自明な事実の羅列や、
内部の関数名・`idle-exit` のような内部用語をそのまま書かない。

## 完了条件

- README(または `docs/architecture.md`)に上記 3 点が書かれており、実装の挙動と一致している
- 実装には手を入れていない
- `npm run lint` / `npm run typecheck` / `npm test` が通る
- `CHANGELOG.md` には載せない(ドキュメントの補足であり、利用者から見た挙動は変わらないため)
