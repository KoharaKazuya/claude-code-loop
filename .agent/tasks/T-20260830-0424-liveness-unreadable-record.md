## 目的

`ccloop status` のループ生存表示で、「記録が無い(本当に起動していない)」と
「記録が読めない(判定できない)」を区別する。

## 現状

`lib/liveness.ts` の `readRunnerRecord` は、記録ファイルが存在しない場合も、権限エラーや
I/O エラーで読めない場合も、一律 `null` を返す。`evaluateLoopLiveness` はそれを
`no-record`(=「動いていません」)として扱うため、実際にはループが動いているのに
「動いていません」と表示されうる。

タスク `T-20260830-0342-status-loop-liveness` の設計方針は「判定できないときは正直に
『不明』と出す」であり、この経路はその方針から外れている。

## やること

- 記録の読み取り失敗を「ファイルが無い」と「読めなかった」に区別する
  (`ENOENT` かどうかで分けるなど)。壊れた JSON・型不正は現状どおり扱ってよい
  (ファイルはあるが記録として使えない、という意味では「読めなかった」側でもよい。
  どちらに寄せたかを判断として残すこと)。
- 「読めなかった」場合は `unknown` を返し、理由が分かる文言を表示する。
- `--json` 出力の既存構造を壊さないこと(値の追加のみ)。

## 補足

state ディレクトリは通常は実行ユーザーの専有なので発生頻度は低い。誤りの向きも
「動いているのに動いていないと出る」側(最も避けたい誤りの逆)なので、優先度は低い。

## 完了条件

- 記録が読めない場合に `unknown` になる回帰テストがある。
- `npm run` 経由の test / typecheck / lint が通る。
