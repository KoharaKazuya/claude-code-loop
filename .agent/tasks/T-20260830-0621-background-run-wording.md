`HR-20260830-0429-topic-run-stop-handle` で人間の回答を得た。

## 決まったこと

回答は「**このままで。ドキュメントに「裏で動かす」というバックグラウンドジョブの推奨みたいな
記述があれば修正して。ccloop run を起動したターミナルを起動しっぱなしにする使い方を想定している**」。

つまり:

- **不採用**: ループの居場所(プロセス番号)を記録して `ccloop status` に表示する案。
  停止の導線を増やす変更は行わない。
- **採用**: 想定される使い方は「`ccloop run` を起動した画面をそのまま開いておく」であり、
  それに反する記述を直す。

## やること

1. 「バックグラウンド/別プロセスで起動する」ことを推奨と読める記述を洗い出して直す。
   少なくとも `lib/help.ts:35` と `lib/help.ts:50` に該当する記述がある。
   `README.md` と `docs/` も確認すること。
2. 直し方の方針:
   - 想定する使い方が「起動した画面を開いたままにする」ことだと分かる書き方にする。
   - `run` が常駐して動き続けるプロセスであるという**事実の説明は残す**(これは利用者が知る
     必要がある)。変えるのは「だから裏で動かすとよい」という**推奨の部分**である。
   - エージェントから使う場合の記述(`lib/help.ts:50` 付近)も、推奨として書かれているなら
     同様に改める。使い方の説明として必要なら残してよいが、人間向けの推奨と読めないようにする。
3. 停止方法の説明は現状のまま(起動した画面で Ctrl+C)でよい。停止信号まわりの追記は
   今回の回答の範囲外なので行わない。
4. 文書だけの変更であれば `CHANGELOG.md` への追記は不要(利用者から見た挙動は変わらない)。
   ただし `lib/help.ts` の表示文言は利用者の目に触れるので、案内が実質的に変わると判断したら
   1 行足すこと。判断に迷ったら足さないでよい。

## 完了条件

裏で動かすことを勧める記述が残っていないこと。機械的検証(lint / typecheck / test)が通ること。
