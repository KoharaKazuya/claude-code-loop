## 目的

実行中のタスクが 0 件のとき、それが「たまたま手が空いている」のか「ループ本体が落ちていて
誰も何も進めていない」のかを `ccloop status` の表示から区別できるようにする。

## やること

- `ccloop run` が実行中であることを示す情報を状態に記録する(記録先は状態ディレクトリ。
  リポジトリには置かない)。
- `ccloop status` で、その情報をもとにループ本体が今も生きているかを確かめ、
  「動いています / 動いていません」を 1 行出す。
- あわせて状態が最後に更新された時刻を出す(いつの情報を見ているかが分かるようにするため)。

現状は `lib/supervisor.ts:4452` 付近が最後の巡回時刻を出しているだけで、ループ本体の
生死は表示されていない。

## 設計上の注意

- 「記録が残っているか」だけでは生死を判定できない。`ccloop run` が異常終了した場合、
  記録は残ったままになる。プロセスが実際に生きているかを確かめる手段(PID の存在確認など)を
  併用すること。
- 別のマシン・別のコンテナで動かした状態ディレクトリを読む可能性がある。PID の存在確認が
  当てにならない状況では「不明」と正直に出す。生きていないのに「動いています」と出すのが
  最も避けたい誤りである。
- `ccloop status --json` の出力にも同じ情報を含める(既存の JSON 出力の構造を壊さないこと)。

## 完了条件

- `ccloop run` 実行中と非実行中で `ccloop status` の表示が変わることを確認する回帰テストがある。
  異常終了で記録が残ったままのケースも検証する。
- `npm run` 経由の test / typecheck / lint が通る。
