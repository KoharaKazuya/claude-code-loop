## 背景

`ccloop status` の「要対応」に出る「退避された衝突ブランチ」は、いまブランチ名を並べるだけである。
中身が既に main へ取り込まれていて消すだけのものか、まだ誰も見ていないものかが表示から区別できない。
実際に 3 本並び、うち 2 本が取り込み済みという状況が起きた。区別が付かないまま積み上がると、
放置されるか、消してはいけないものを消す事故につながる。

## やること

1. `collectPendingConflicts`(`lib/supervisor.ts` 付近。`ccloop status` の該当セクションを組み立てている箇所)で、
   退避ブランチごとに「中身が main に含まれているか」を判定する。
2. 判定結果に応じて 2 群に分けて表示する。
   - **取り込み済み・削除してよい**: 削除コマンド(`git branch -D <branch>`)を添える
   - **未取り込み・要確認**: 現状どおりブランチ名のみ(内容を確認して統合か破棄を判断、の案内)
3. テストを足す。
4. `CHANGELOG.md` の「## 未リリース」に利用者の言葉で 1 行足す。

## 判定の条件(人間が付けた条件。必ず守ること)

**判定は安全側に倒す。** 確信が持てない場合は必ず「未取り込み・要確認」側へ出す。
「取り込み済み・削除してよい」と断定してよいのは、機械的に確実に判定できる場合に限る
(例: `git log main..<branch>` が空、すなわち到達可能なコミットが全て main に含まれている)。

**patch-id ベースの判定だけを根拠に「削除してよい」と表示してはならない。** 取り込み時に
コミットが再構成される(手で当て直す・squash される)と外れることが、このリポジトリで実例として
確認されている。中身が別の形で作り直されて main に入った場合に「未取り込み」と出るのは
許容される(安全側の外れ方)。

## 完了条件

`ccloop status` で退避ブランチが 2 群に分かれて表示され、取り込み済み側にだけ削除コマンドが付くこと。
判定が安全側に倒れていることをテストで担保していること。機械的検証が通ること。

## 注意

ブランチの削除は従来どおり ccloop 側では行わない(人間に渡す)。表示にコマンドを添えるだけである。
