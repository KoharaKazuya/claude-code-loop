所属フェーズ: 4(思いつく改善すべて)。人間の確認は不要な修理として登録する。

## 症状

人間がタスクファイルの `dependencies` に、打ち間違いなどで実在しないタスク ID を書くと、
その依存は「満たされている」ものとして扱われ、タスクは即座に実行対象になる。
警告も出ないため、人間が意図した順序が黙って崩れる。

`ccloop task create` 経由の新規作成は依存の存在を検証するが、既存ファイルを手で編集した場合は
この検証を通らない。

## 原因(調査済み)

`lib/supervisor.ts` の `depSatisfied`(1631 行付近)は、依存 ID が一覧に見つからない場合に
「満たされている」を返す。`selectRunnable`(1682 / 1716 行付近)が渡す一覧は現役の
`.agent/tasks/` だけから作られる。

確認済みの事実: 上記はコード読解で確認済み。`ccloop task list` は archive も含めた一覧で
`(missing)` と表示するが、満たされている扱いのまま淡色表示になるため目立たない
(`lib/supervisor.ts:4215-4224` 付近)。
未検証の推測: 実機での再現は未実施。

## 重要な制約(単純に「不明な依存は未達」としないこと)

完了したタスクは `.agent/archive/tasks/` へ移動され、現役の一覧から消える。したがって
「現役の一覧に無い依存」には **完了済み** と **そもそも存在しない** の 2 種類がある。
前者を未達扱いにすると、完了済みタスクに依存するタスクが永久に実行されなくなる。

archive も含めて探し、archive にあれば従来どおり満たされている扱いにし、
どこにも無いものだけを「存在しない依存」として区別すること。

## 完了条件

- どこにも存在しない依存 ID を持つタスクが、`ccloop status` の「要対応」に人間の言葉で表示される
  (どのタスクのどの依存が存在しないか。既存の不正なタスクファイルの表示と揃える)
- 完了済み(archive にある)タスクへの依存は従来どおり満たされている扱いのままであることを
  テストで固定する
- スケジューリング上の扱いを変える場合(存在しない依存を未達にして実行を止めるか、
  従来どおり実行するか)は判断を `.agent/decisions/` に記録する。人間が気づけることを
  優先し、ループが静かに止まる方向へは倒さないこと
- typecheck / lint / test が通る
