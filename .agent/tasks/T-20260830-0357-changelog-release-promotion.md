## 経緯

`T-20260830-0341-changelog-initial` が `CHANGELOG.md` を新設し、
`T-20260830-0341-changelog-update-rule` が「変更を入れたセッションが未リリース節へ 1 行足す」運用を
定めた。しかしリリース時に未リリース節を確定版の見出し(`## 0.5.0 — 2026-XX-XX`)へ繰り上げる
段取りが、どこにも存在しない。`scripts/release.mjs` は `CHANGELOG.md` に触れていない
(リポジトリ内で `CHANGELOG` を参照しているのは `README.md` と `.agent/` の記録のみ)。

このままだと、リリースを重ねても全項目が「未リリース」に積み上がり、
「未リリースはまだ公開版に含まれていない変更」という同ファイル冒頭の説明が事実に反する状態になる。

## 目的

リリース操作と変更履歴の見出しが必ず一致する状態にする。

## やること

次のどちらを採るか判断し、理由を `.agent/decisions/` に記録したうえで実装する。

- **A: `scripts/release.mjs` に組み込む** — バージョンを確定する時点で、`## 未リリース` の下の内容を
  `## <新バージョン> — <日付>` の節へ移し、空の未リリース節を残す。`--dry-run` では変更しない。
- **B: 手順として明文化する** — リリース前の確認項目に加え、繰り上げ忘れを検出する検証
  (未リリース節が空でないままタグを打とうとしたら止める、など)を入れる。

判断材料: `scripts/release.mjs` が現状どこまで自動化しているか(バージョン整合の確認・検証・タグ付け・
push)と、繰り上げ内容に人間の推敲が要るか。A なら忘れようがないが、機械的な切り貼りが
意図と食い違ったときに気づきにくい。

## 完了条件

- リリース時に未リリース節が繰り上がる(または繰り上げ忘れが検出される)ことが、テストで確認できる。
- `--dry-run` が変更操作をしないという既存の性質を壊していない。
- `npm run` 経由の test / typecheck / lint が通る。
