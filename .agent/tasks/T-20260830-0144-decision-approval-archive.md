## 目的

`.agent/decisions/` のアーカイブ条件を現在の件数基準(直近 10 件を残す)から
「人間が決定をチェック(承認)したらアーカイブする」に変更する。あわせて
`.agent/decisions/index.md` というインデックスファイルを導入し、人間がどの決定まで
読んだか・承認したかをチェックリストで管理できるようにする。

## 背景

現在は `lib/rotate.ts` の `DECISIONS_KEEP = 10` により、idle 時のローテーションで
古い決定が人間の確認を経ずに機械的に `.agent/archive/decisions/` へ移動される。
人間が決定内容をレビューする前にアーカイブされてしまうため、レビュー済みのものだけを
アーカイブする運用に変える。

## 仕様

### index.md の形式

`.agent/decisions/index.md`(小文字)。1 決定 1 行のチェックリスト。新しい順(ID 降順)。

```markdown
# 決定インデックス

チェック `[x]` を付けた決定は、次回ローテーションでアーカイブされる。

- [ ] [D-20260101-0000-example-slug](D-20260101-0000-example-slug.md) — 1 行要約
```

冒頭の見出し・説明文の文言は上記を目安に実装時に調整してよい。行の書式
(`- [ ] [<ID>](<ID>.md) — <要約>`)はパース対象なので固定する。

### rotate.ts の変更

decisions のローテーション(`lib/rotate.ts`)を以下の 2 段階に置き換える。
`DECISIONS_KEEP` による件数基準は廃止する。

1. リコンサイル(インデックスの整合):
   - `.agent/decisions/` 内の決定ファイル(`D-` で始まる `.md` のみを対象とし、
     `index.md` 自身は対象外)のうち、index.md に行が無いものを `- [ ]`(未チェック)で
     追記する。要約はその決定ファイルの frontmatter `title` を使う。
   - index.md にあるが実体ファイルが存在しない行は削除する。
   - index.md が存在しなければこの処理で新規作成する(既存リポジトリのブートストラップ)。
   - 行順は ID 降順(新しい順)に正規化する。人間が付けたチェック状態は維持する。
2. アーカイブ:
   - `[x]` が付いた行の決定ファイルを `.agent/archive/decisions/` へ移動し、
     該当行を index.md から削除する(経緯は Git 履歴で追える。アーカイブ側に
     別インデックスは作らない)。

既存の冪等設計(対象が無ければ何もしない、書き換えが発生しないなら index.md に
触れない)を維持する。既に旧ルールでアーカイブ済みの決定は遡及して扱わない。

### ドキュメント更新

- `lib/prompt/PROMPT.md`:
  - 決定ファイルを書いたエージェントは index.md へ 1 行(未チェック、自分で書いた
    1 行要約)を追記する義務を明記する(リコンサイルはフォールバック)。
  - decisions のアーカイブ条件の記述(「直近 10 件ローテーション」への言及。
    ID 形式の節の「decisions の直近 10 件ローテーションはこの前提で動く」も含む)を
    新ルールに更新する。
- `docs/`(architecture.md 等)と `README.md` に旧ルール(件数基準)の記述があれば
  新ルールに更新する。

## 完了条件

- `lib/rotate.ts` が上記仕様どおり動作し、リコンサイル・承認済みアーカイブ・
  index.md 除外・冪等性を検証する単体テストが追加されている。
